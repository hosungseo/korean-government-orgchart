# Windows 한글 편집형 HWPX 앱

이 앱은 조직도를 그림 한 장으로 넣지 않습니다. 작도 명세의 각 항목을 Windows에 설치된 한컴오피스 한글 Automation으로 전달하여 다음 개별 객체를 생성합니다.

- 조직 상자: 한글 사각형·글상자 객체
- 조직명: 각 글상자 안의 편집 가능한 문자
- 계선: 각각 독립된 한글 선 객체
- 평가대상 표식: 독립된 점선 사각형 객체

내장 샘플은 행정안전부 `인공지능정부실`과 `참여혁신조직실`을 A4 세로 왼쪽면에 배치합니다. 앱의 **직제·시행규칙 붙여넣기** 창에서 두 법령 원문을 바로 입력해 조직도 명세를 만들 수 있습니다. 작도 범위에 `인공지능정부실, 참여혁신조직실`처럼 여러 조직을 지정하면 한 장에 묶고, 비워두면 전체 구조를 개요·본부 하부조직·소속기관으로 자동 분할합니다. `*.native.json` 선택·드래그앤드롭 방식도 유지됩니다.

0.7은 Windows 한글 편집본의 정확성과 검증에 집중합니다.

- 직제·시행규칙을 `조 → 항 → 호 → 목`으로 읽고, `1의2` 가지번호와 여러 줄 기능 문언을 보존합니다.
- 과별 각 호 기능을 양쪽 시점에서 대조해 개명·분할·통합의 점선 후보를 만들고, 조문 근거와 신뢰도를 함께 남깁니다.
- 동일 명칭이 존속하면 거짓 분할선을 만들지 않습니다. 개정문 명시 대응이 기능 유사도보다 우선합니다.
- 삭제호·잔여호는 기능 승계 비율에서 제외하고, 근거가 부족하거나 후보가 경합하면 자동 작도하지 않고 검토 대상으로 남깁니다.
- 시행규칙에서 소관 과가 확인된 정책관·기획관은 국처럼 하위 과를 거느려 표시하되, 원본 법적 그래프의 보좌기관 유형과 설치 계선은 보존합니다.

문언 파서는 설치본에 함께 들어가므로 실행 PC에 Node.js가 필요하지 않으며, 입력 원문은 외부로 전송하거나 HWPX에 통째로 넣지 않습니다. 직제 본문은 실·국·소속기관을, 시행규칙은 과·담당관·팀을 보강하므로 정확한 과 단위 조직도에는 두 원문을 함께 넣는 것이 원칙입니다.

불러온 명세는 한글을 열기 전에 다음 항목을 검사합니다.

- A4 세로 또는 A3 가로 경계와 여백. 2단 대비는 A4, 3단 이상은 A3 가로로 한글에 생성합니다.
- 객체 ID 중복과 지원 객체 유형
- 한글 Automation이 처리할 수 있는 색상·글꼴·정렬·좌표
- 명세의 예상 객체 수와 실제 객체 수
- `childId`가 있는 계선이 자식 상자 경계에 맞물리는지

오류가 있으면 생성을 막고, 끊긴 접합이나 대각선처럼 확인이 필요한 항목은 경고로 표시합니다. 저장한 HWPX를 Automation으로 다시 열어 `선택한 용지 1쪽`과 `네이티브 객체 수 일치`를 확인한 경우에만 앱 화면에 검증 통과를 표시합니다.

## 요구 환경

- Windows 10/11
- 한컴오피스 한글(Automation의 `HWPFrame.HwpObject`가 등록된 버전)
- 한컴 개발자센터에서 제공하는 파일 접근 보안모듈(Automation) 설치·등록
- WebView2 Runtime(Tauri 설치본에 부트스트래퍼 포함)

Node.js나 Python은 설치본 실행 시 필요하지 않습니다. 개발·빌드할 때만 Node.js와 Rust가 필요합니다.

## 개발 실행

Windows에서 저장소 루트를 기준으로 실행합니다.

```powershell
npm ci
npm ci --prefix desktop
npm run desktop:dev
```

`desktop:dev`는 다음 작업을 순서대로 수행합니다.

1. 행안부 두 실 내장 명세와 브라우저용 직제 파서 준비
2. Tauri 앱 실행
3. 직제·시행규칙 문언 붙여넣기 또는 외부 `*.native.json` 불러오기
4. 조직 추출, A4 자동 분할, 계선–상자 접합 사전검사
5. 한글 Automation 설치 확인
6. 사용자가 생성 버튼을 누르면 현재 미리보기 쪽의 네이티브 HWPX 생성·재열기 검증

산출물은 기본적으로 `%USERPROFILE%\Documents\직제기구도`에 저장됩니다. 같은 파일명이 있으면 기존 파일을 덮지 않고 시각값을 붙여 새 파일로 저장합니다. 재현과 감사에 필요한 파일도 같은 이름으로 함께 남깁니다.

- `이름.hwpx`: 한글 편집형 조직도
- `이름.native.json`: 실제 생성에 사용한 작도 명세
- `이름.verification.json`: 사전검사와 한글 재열기 결과
- `이름.legal-evidence.json`: 각 점선의 출발·도착 조직, 판정 방식, 신뢰도, 대응 조문과 기능 문언

네 파일은 숨김 임시 파일에 먼저 생성됩니다. 한글 Automation으로 HWPX를 다시 열어 쪽수와 객체 수를 확인하고, 최종 파일의 SHA-256을 재검증한 뒤에만 한 묶음으로 확정합니다. 어느 단계든 실패하면 부분 파일을 남기지 않습니다.

## 3~4개 기준일 HWPX 대비표 만들기

1. 직제·시행규칙을 입력하거나 공식 API에서 기준일 조직을 불러옵니다.
2. `현재 조직도 이력 저장`으로 필요한 기준일을 로컬 이력 DB에 저장합니다.
3. 1열부터 4열까지 기준일을 고르고 `대비 조직도 보기`를 누릅니다.
4. A3 대비표에서 조직 배치, 신설·폐지, 기능 근거 점선을 확인합니다.
5. `한글 편집본 만들기`를 눌러 HWPX와 세 근거·검증 파일을 함께 저장합니다.

이전 버전의 영상 내보내기 구현은 호환을 위해 코드에 남아 있지만 0.7 UI에서는 숨기며, 제품의 기본 작업 흐름과 검증 대상에 포함하지 않습니다.

## 큰 대비표(객체 수백~수천 개)에서 한글이 멈추거나 종료될 때

3~4단 대비표는 한글 표가 아니라 선·사각형·글상자를 한글 Automation으로 하나씩 만드는 방식입니다. 객체 수백~수천 개를 한 프로세스에서 이어 만들다 한글이 멈추거나 종료되는 정확한 원인은 아직 확정되지 않았습니다(추정: 32비트 한글의 메모리 누적, 모달 대화상자, 특정 객체). 0.8.1부터 생성 루틴은 원인이 무엇이든 견디고 지점을 남기도록 다음처럼 동작합니다.

- **청크 체크포인트**: 객체 150개마다 HWPX를 임시 폴더에 저장하고 한글 프로세스를 완전히 내린 뒤, 새 한글로 저장본을 열어 이어 그립니다(`hwp-native.ps1 -ChunkSize`).
- **크래시 자동 재개**: 한글이 응답을 끊거나 종료되면(RPC 단절·프로세스 소멸) 마지막 체크포인트부터 청크를 절반으로 줄여(하한 25, 이후 유지) 같은 자리에서 최대 3회, 전체로는 최대 20회 다시 이어 그립니다. 그 외 오류는 즉시 실패로 보고합니다.
- **정체 감지·중단**: 한글이 살아 있는 채 멈추면(모달·내부 교착) 5분간 진행이 없을 때 한글 프로세스만 강제 종료해 재개 경로를 깨우고, 4회를 넘기면 생성을 중단합니다. 화면의 `생성 중단` 버튼으로 언제든 멈출 수 있고, 앱을 닫아도 PowerShell·숨김 한글이 남지 않습니다.
- **진행 표시·진단 로그**: 화면에 `객체 N/M · 세션 K · 남은 시간` 이 실시간으로 뜹니다. 실패하면 오류 메시지에 실패 객체 번호·ID·유형, 저장된 객체 수, 로그 꼬리, 진단 로그 경로가 붙습니다(경로를 그대로 복사하면 됩니다). 로그에는 객체별 유형·문자 수·소요 ms 와 10객체마다 한글 메모리·핸들 수가 남습니다. 실패해도 마지막 체크포인트(`checkpoint.hwpx`, 선→사각형→글상자 순으로 N개까지)는 같은 진단 폴더에 남아 구제·재현에 쓸 수 있습니다. 진단 폴더는 최신 5개·7일까지만 보관합니다.
- **타임아웃과 고아 정리**: 전체 상한은 객체 수에 비례합니다(객체당 3초, 최소 10분, 최대 4시간). 중단할 때 이 앱이 띄운 숨김 한글 프로세스(이미지명 Hwp.exe 확인 후)도 함께 종료해, 다음 시도가 남은 한글 때문에 흔들리지 않게 합니다.
- **메모리·시간 기준 조기 저장**: 한글은 2024까지 32비트(2GB 상한)라 프로세스 메모리를 10객체마다 재고, 1.2GB를 넘거나 한 세션이 120초를 넘으면 청크 끝을 기다리지 않고 저장 후 프로세스를 갈아 끼웁니다(`-MemoryLimitMb`, `-SessionMaxSeconds`). 로그에 `hwp memory NNNMB` 가 함께 남습니다.
- **한글 창은 모두 닫고 실행**: 한글 2024는 Automation 개체를 여러 개 만들어도 한글 프로세스를 하나만 두는 문제가 있어(한컴 확인), 사용자의 한글이 떠 있으면 앱이 그 창에 붙어 버립니다. 앱은 이를 감지하면 사용자의 문서를 건드리지 않고 "열려 있는 한글 창을 모두 닫은 뒤 다시 시도하세요"로 멈춥니다. 이전 실행이 남긴 자동화 한글(명령줄 `-Automation`)은 시작 전에 자동 정리합니다.
- **창을 새로 열지 않음**: 숨김 인스턴스에서 `FileNew` 를 실행하면 보이는 창이 새로 뜰 수 있어(사용자가 건드리면 편집 포커스가 깨짐) 새 문서를 만들지 않고 초기 빈 문서를 비워 씁니다. 창은 탭·새 창까지 전부 숨깁니다.

그래도 같은 자리에서 반복 실패하면 오류 메시지의 실패 객체 ID와 `progress.json.log` 의 소요 시간·메모리 추이를 확인하세요. 특정 글상자에서만 죽는다면 그 객체의 문자열·서식이 원인이고, 객체 수에 비례해 느려지다 죽는다면 앱에서는 대비표 열 수를 줄이거나 실 단위로 나눠 두 장으로 만드는 것이 먼저입니다(스크립트를 직접 실행할 때는 `-ChunkSize 50 -MaxRecoveries 5` 처럼 조정; 앱 기본은 150·3). 한글 자체 예외 로그도 켤 수 있습니다: `%APPDATA%\HNC\User\Common\<버전>\optionInfo.xml` 의 `EnableExceptionLog` 값을 1로 바꾸고 재현하면 `%APPDATA%\HNC\Log\Hwp` 에 ExceptionLog 가 남습니다(한컴 개발자포럼 안내). 이 파일과 `progress.json.log` 를 함께 보면 한글 쪽 원인까지 좁힐 수 있습니다.

## Windows 설치본 빌드

```powershell
npm ci
npm ci --prefix desktop
npm run desktop:build
```

NSIS 설치본(`*.exe`)은 `desktop/src-tauri/target/release/bundle/nsis` 아래에 생성됩니다. GitHub Actions의 `Build Windows native HWPX studio` 워크플로도 같은 빌드를 수행합니다.

## 한글 없는 환경에서 가능한 검증

작도 명세의 스키마·객체 수·중복 ID·A4/A3 용지 경계는 Node 테스트로 검사합니다.

```powershell
npm test
node scripts/build-mois-ai-participation-native-manifest.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File desktop/src-tauri/resources/hwp-native.ps1 `
  -Mode ValidateManifest `
  -ManifestPath desktop/src-tauri/resources/mois-ai-participation-left.native.json
```

개별 객체가 실제 한글에서 편집되는지와 A4 1쪽으로 저장되는지는 한글이 설치된 Windows에서만 최종 확인할 수 있습니다.

한글이 설치된 Windows 개발 PC에서는 다음 한 줄로 실제 생성·재열기 검증을 바로 실행할 수 있습니다.

```powershell
npm run --prefix desktop verify:windows
```

검증을 통과하면 `A4 1쪽 · 네이티브 객체 86개`가 표시되고 생성 파일이 한글에서 열립니다.

## 보안·라이선스

한글의 파일 접근 보안모듈이 등록되지 않은 PC에서는 생성 버튼을 비활성화하고, 명령을 직접 호출해도 즉시 중단합니다. 저장 승인창을 우회하지 않으며, [한컴 Automation 안내](https://developer.hancom.com/hwpautomation)에서 공식 보안모듈을 내려받아 설치·등록한 뒤 사용해야 합니다.

한글 Automation은 개인·비상업 용도로 자유롭게 이용할 수 있지만, 상업용 솔루션이나 응용프로그램에 사용하려면 한컴의 별도 승인이 필요합니다. 배포 전 [한컴 Automation 안내](https://developer.hancom.com/hwpautomation)를 확인해야 합니다.
